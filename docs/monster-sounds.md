# Monster sounds and Steve's lines on randomized floors

A monster's sounds live in its home dungeon's sound set, and Steve's lock-on lines about it in its home dungeon's Steve file,
so a species the randomizer placed anywhere else was silent and Steve had nothing to say about it. Each randomized floor now
loads a monster bank built from the sounds of the species on it, and Steve's lines for them.

## How the game plays a monster sound

- Entering a dungeon loads `sound\set\snd{100 + selectMapNo}.snd` (`GameInit` → `SndSoundLoad`): banks `*_c`, `m01a_e`,
  `d01a_i`, the monster bank `*_g`, and `sysa_m`. Demon Shaft's five floor bands are five map numbers (snd106–110). Nothing reloads
  a set during a visit.
- A monster sound id (601–2596) resolves through one static table, `se_info` (ELF 0x25DFB0, 6-byte rows), to a (program, note)
  played on MIDI port 10, the monster bank's (`CSound::LoadHdBd_G` binds it). Each set's monster bank holds only its natives'
  sounds.
- A species plays ids from its script (`_SET_SND_NOW`, `_SET_SND_FRM`, `_SET_LOOP_SND`), its model's `EVENT frame, 1, id` cfg
  lines and the `sound[4]` of its shot configs (BT_SHOT_EFFECT +0x60).
- A program carries up to three species' sounds, each on its own 30-note window (notes 20–49, 50–79, 80–109); a set carries only
  its natives' windows. A (program, note) is the same sound in every set that has it: all 170 shared ones match.
- Bank format (`.hd`): a version chunk, a head chunk (sizes and the four chunk offsets at +0x24–0x30), then VAG (8 B), sample
  (42 B), sample-set (6 B, one sample each) and program chunks (36-byte header + 20-byte splits), each a 16-byte header (tag,
  size, max index), an offset table and the records. The `.bd` holds the VAG samples.

## The pieces

| Part | Where | What it does |
|---|---|---|
| Library | `MonsterSoundBake` (post-bake `monster-sounds`) → `sound\set\monlib.snd` | Every (program, window) unit of the eleven dungeon sets gathered across them: the union of their sounding splits, records indexed from 0, samples deduplicated by content. A front read whole (header, a 512-entry unit directory, species → units, per-map kept units, the records), then each unit's samples sector-aligned. 4.1 MB, front 47.6 KB. The dead backup entry `dun\monstor\e50a.chr_` renamed in place. |
| Species → units | `MonsterSoundBake.SpeciesUnits`, generated by `tools/analysis/gen_species_sound_units.py` | Per species-table index, up to two units (program × 4 + window). The extension rows (Bomb, Crystal Gemron) play Holy Gemron's script, so Holy's unit; the Crystal Gemron adds the shatter unit. |
| Life sphere shatter | `MonsterSoundBake.Shatter` + `ElfSoundPatches` | The sound the life sphere's cutscenes play as it breaks (id 312 → program 45, note 112 of set 202's monster bank) for the Crystal Gemron's death: decoded, cut at 2.4 s, halved to 22,050 Hz, sped up 2× at the same pitch (overlap-added Hann grains), the last 0.12 s faded and re-encoded (`VagAudio`) as unit 45 × 4 + 3 (note 112 lies past the dungeon windows). se_info's unused row 600 is set to (45, 112, port 10), so id 600 plays it on the monster port wherever the species is. |
| Kept units | the library's per-map table | Units a dungeon's own bank sounds that no species owns (program 44 in Divine Beast Cave, 46 in Moon Sea): sounds played through the dungeon's basic tables, kept in its floors' banks. |
| Cave | `tools/stubs/monster_bank.s` (dead soft-float routines, 0x110848) + `monster_bank_io.s` (dead CD streaming routines, 0x10BEB8) | Hooked at `BtLoadMonstor`'s closing `jal MemoryMapDump` (dun 0x01DB9568): the floor's species are loaded, its layout row is in `s1`, `read_buffer` is free. It finds the library with `SearchFile`, reads its front, collects the floor's units, reads their samples under the cap, composes the bank header in the game's layout and calls `LoadHdBd_G`. |
| Gate | `Gate` in `monster_bank_io.s` | Builds on a floor whose bit is set in `CodeCaves.MonsterBankFloors`, or on any floor while the monster port still holds the bank it built (its IOP header address, `MonsterBankStats + 0x10`, against `midi_state.port[3].bank`) — so a vanilla floor after a randomized one gets its natives back. A floor none of whose species is in the library (a boss floor) is left alone. |
| Steve's lines | `Steve` in `monster_bank_io.s`, the library's Steve blocks | Steve's lock-on lines are messages 4000 + the monster's name number × 10 + 0–9 of the dungeon's `SteveNN_1.mes` (`BtMapJumpLoad` loads it into Steve's window, `DngMesStb`), each file only its natives'. The library holds one block per species (its own ids, the first file's text that has it; the Bomb and Crystal Gemron take Holy Gemron's texts with their own lines 0–1 over them, `EnemyDefaults.SteveLines`), at most 6 KB. Whenever the cave builds a floor's bank it rewrites Steve's buffer (`BtSteebMesBuffer`, 56,000 B) as a message file of the floor's species' lines and gives it to `ClsMes::SetBuff` again. |
| Mod | `Enemies/MonsterSounds.cs` | Marks each floor `EnemyRandomizer` stages, clears it when un-staged and all of them on the dungeon's restore; logs every bank built. |

## Limits

- **Cap:** the lesser of 456,720 B (the largest monster bank vanilla loads, so the sound processor and the IOP heap are proven
  for it) and the room between the dungeon's E bank and the I bank in sound memory. Units load in order — kept units, then each
  species in roster order — and a unit that does not fit is left out, its species silent. A typical roster is 300–420 KB.
- **Bosses:** their programs (112–121) live in the boss arena sets and are not in the library; the randomizer never places them.
- **Load time:** the library's front (24 sectors), the floor's units (about 0.3–0.4 MB) and its Steve blocks (a few sectors) are read
  during the floor load.

## Testing

`monster_bank.s` was run in unicorn with mocked `SearchFile`, `sceCdRead` (serving the real library), `LoadHdBd_G` and game
globals: every note of each composed bank plays the same sample bytes as the original sets, two windows of one program merge
under one program record, registers come back intact, and the gate skips unmarked floors, floors after a set reload and boss
floors. The Steve pass, against the same mocks plus a Steve buffer and `SetBuff`, writes exactly the floor's species' lines with
the original texts. In-game testing is still needed.
